## Lecture 1: What is Cloud Computing?

### Definitions — Memorise These

**NIST definition (2011 — the standard):**
> "Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction."

Key elements of NIST definition:
- **On-demand self-service:** Consumer provisions computing capabilities automatically without human interaction with the provider
- **Broad network access:** Available over the network and accessed through standard mechanisms (phones, tablets, laptops, workstations)
- **Resource pooling:** Provider's computing resources are pooled to serve multiple consumers using a multi-tenant model, with different physical and virtual resources dynamically assigned and reassigned
- **Rapid elasticity:** Capabilities can be elastically provisioned and released to scale rapidly outward and inward commensurate with demand
- **Measured service:** Cloud systems automatically control and optimise resource use by leveraging a metering capability (pay-per-use)

**Thomas Erl definition:**
> "Cloud computing is a specialized form of distributed computing that introduces utilization models for remotely provisioning scalable and measurable resources."

### Cloud Terminology — Know These

| Term | Definition |
|------|------------|
| **Cloud service** | Any IT resource that is made remotely accessible via a cloud |
| **Cloud provider** | A company or third-party that offers cloud computing services |
| **Cloud consumer** | An organisation or person with a formal contract/agreement with a cloud provider to use IT resources |
| **Cloud service owner** | A person/organisation that legally owns a cloud service |
| **Cloud resource administrator** | A person/organisation responsible for administering cloud-based IT resources (including cloud services) |
| **Cloud carrier** | Provides connectivity between cloud consumers and cloud providers |

### Cloud Service Models — The Core Concept

**IaaS (Infrastructure as a Service):**
- Cloud consumer uses a virtual server within an IaaS environment
- Consumer is provided with contractual guarantees pertaining to capacity, performance, and availability
- Provider manages: physical hardware, networking, storage, hypervisor
- Consumer manages: OS, middleware, runtime, applications, data
- **Example:** AWS EC2, Azure Virtual Machines

**PaaS (Platform as a Service):**
- Cloud consumer accesses a ready-made PaaS environment
- Consumer is intentionally shielded from implementation details of the platform
- Provider manages: hardware, OS, middleware, runtime
- Consumer manages: applications, data
- **Example:** Azure App Service, AWS Elastic Beanstalk

**SaaS (Software as a Service):**
- Cloud service consumer given access to the cloud service contract, but NOT to any underlying IT resources or implementation details
- Provider manages everything
- Consumer manages: nothing (just usage/configuration)
- **Example:** Office 365, Salesforce, Dropbox

### Physical Topology of VMware Infrastructure Data Centre

(from Lecture 1 slides)

- Physical data centre contains racks of physical servers
- Each physical server runs a hypervisor (ESXi)
- Hypervisors manage VMs on that server
- All hypervisors across servers are jointly controlled by a VIM (Virtual Infrastructure Manager — vCenter)
- Storage is typically SAN (Storage Area Network) shared across all servers
- Networking connects everything — physical NICs uplink to physical switches

## Lecture 2: Virtualisation Technologies

### What is Virtualisation?

**Definition:** Abstraction of computer resources. The goal is to collaboratively utilise IT resources to the maximum level and reduce the cost of IT resources.

Virtualisation allows multiple workloads to run on a single physical host by abstracting the underlying hardware.

### Types of Virtualisation

| Type | What it does | Example |
|------|-------------|---------|
| **Processor virtualisation** | Enables a processor to be shared across multiple application instances | vCPU — each VM gets virtual CPUs that are scheduled on physical cores |
| **Memory virtualisation** | Aggregates memory resources into a pool of single memory and manages memory on behalf of multiple applications | VM gets virtual RAM; hypervisor maps virtual memory pages to physical memory frames, possibly across multiple physical servers |
| **Network virtualisation** | Entails virtual IP management and segmentation | vNIC, vSwitch, VLANs — logical networks independent of physical network topology |
| **Storage virtualisation** | Provides a layer of abstraction for the physical storage of data | VM sees virtual SCSI disks; hypervisor maps these to physical storage blocks on SAN/NAS |

### Virtual Machines (Virtual Servers)

- VMs are **isolated instances** of application software and guest operating system that run like a separate computer
- A VM **encapsulates** the virtual hardware, virtual disks, and the metadata associated with the application
- VMs can connect to peripheral devices and function just like physical computers
- Each VM has its own virtual CPU, virtual memory, virtual storage, virtual network adapter

### Hypervisor (Virtual Machine Monitor — VMM)

**Definition:** The hypervisor is responsible for managing the applications' OSs (guest OSs) and their use of system resources (CPU, memory, storage). It supports isolation and manages multiple VMs running on the same host computer.

**Resources provided to each VM:**
- Logical CPU and memory
- Logical storage blocks
- Logical network resources

**Functions of Hypervisors:**
1. Creating and managing VMs
2. Allocating "hardware resources" to VMs from the virtualized pool of hardware resources belonging to the physical server
3. Monitoring the status of the VMs
4. Taking part in the movement of VMs from one system to another (e.g., VMotion / live migration)

### Types of Hypervisors — Exam Important

| | **Bare-metal / Type 1** | **Hosted / Type 2** |
|---|---|---|
| **Runs on** | Directly on hardware (no host OS) | On top of a host operating system |
| **Examples** | VMware ESXi, Microsoft Hyper-V (when installed as role), Xen, KVM | VMware Workstation, VirtualBox, VMware Player |
| **Performance** | Higher — direct hardware access | Lower — goes through host OS layer |
| **Use case** | Production data centres, cloud providers | Desktop testing, development, personal use |
| **Overhead** | Minimal | More (host OS consumes resources too) |

**Exam tip:** Type 1 = production cloud. Type 2 = desktop/testing. Know the difference.

### Typical Cloud Architecture Components

- **Virtual machines** — the workloads
- **Hypervisor** — the virtualisation layer on each physical server
- **Physical servers** — the actual hardware
- **Networks** — connect everything
- **SAN Storage** — shared storage across all servers
- **VIM (Virtual Infrastructure Manager)** — controls all hypervisors jointly (vCenter in VMware)

### Storage Hardware — Three Types

| Type | Description | Connection |
|------|-------------|------------|
| **DAS (Direct Attached Storage)** | Storage system directly connected to a computing IT resource (physical server) using a host bus adapter (HBA) | Inside or directly cabled to the server |
| **NAS (Network-Attached Storage)** | File-level storage accessed over the network | Ethernet, NFS/SMB protocols |
| **SAN (Storage Area Network)** | Block-level storage accessed over a dedicated storage network | Fibre Channel, iSCSI, FCoE |

### Storage Virtualisation

Definition: "The process of presenting a logical view of the physical storage resources to a host computer system, treating all storage media (hard disk, optical disk, tape, etc.) in the enterprise as a single pool of storage."

**Two types:**
1. **Block-level virtualisation:** Abstracts storage at the block level (below the OS/file system)
2. **File-level virtualisation:** Abstracts at the file system level

**Three methods:**
1. **Network-based:** Storage virtualisation appliance sits on the network between servers and storage
2. **Host-based:** Host OS/hypersvisor manages the virtualisation
3. **Array-based:** The storage array itself provides virtualisation

### VMware Storage Architecture

- Storage presented to VMs as **virtual SCSI disks** connected to a virtual Host Bus Adapter (vHBA)
- Virtual SCSI disks inside VMs are provisioned from **Datastore** elements in the data centre
- Datastores abstract the physical storage — VM doesn't know if its disk is on DAS, NAS, or SAN

### VMware Network Architecture

- VMs in a datacentre are like physical machines networked in a physical environment
- Guest OS and applications communicate with a **virtual NIC (vNIC)** through either commonly available device drivers or VMware-optimised device drivers
- **Port groups** aggregate multiple ports under a common configuration and provide a stable anchor point for VMs connecting to labelled networks

## Lecture 3: Cloud Infrastructure & Management Mechanisms

### Infrastructure of Cloud Service Provider

Four technology foundations:
1. **Broadband Networks and Internet Architecture** — all cloud must be connected to a network; internetworks allow remote provisioning of IT resources
2. **Data Center Technology** — facilities (housing, racks, cabling, power, HVAC, fire protection), computing hardware (servers, blade servers), storage hardware (HD arrays, SAN, NAS), network hardware (load balancing, LAN/SAN fabric, NAS gateways)
3. **(Modern) Virtualisation Technology** — servers (physical → virtual), storage (physical → virtual), network (physical routers/switches → logical fabrics like VLANs), power (physical UPS → virtual UPS)
4. **Web Technology and Service Technology** — web as implementation medium and management interface; service technology (web services, WSDL, XML schema, SOAP, UDDI, REST, service agents, service middleware) as the keystone foundation

### Cloud Infrastructure Mechanisms — 6 Types

These are the fundamental building blocks of cloud infrastructure:

| # | Mechanism | Description |
|---|-----------|-------------|
| 1 | **Logical Network Perimeter** | Isolation of a network from the rest of a communications network. Two logical network perimeters surround the cloud consumer and cloud provider environments |
| 2 | **Virtual Server** | Form of virtualisation software that emulates a physical server. Hosts an active cloud service and is accessed by cloud consumer for administrative purposes |
| 3 | **Cloud Storage Device** | Storage devices designed specifically for cloud-based provisioning. Different cloud service consumers use different technologies to interface with virtualized cloud storage devices |
| 4 | **Cloud Usage Monitor** | Autonomous software program responsible for collecting and processing IT resource usage data. Types: Monitoring Agent, Polling Agent, Resource Agent |
| 5 | **Resource Replication** | Creation of multiple instances of the same IT resource. Hypervisor replicates several instances of a virtual server using a stored virtual server image |
| 6 | **Ready-made Environment** | Defining component of PaaS cloud delivery model equipped with a complete software development kit. Cloud consumer accesses a ready-made environment hosted on a virtual server |

### Cloud Management Mechanisms — 4 Types

| # | Mechanism | Description |
|---|-----------|-------------|
| 1 | **Remote Administration System** | Enables cloud resource administrators to configure leased virtual servers, provision new cloud services via self-service portals, and manage cloud services remotely |
| 2 | **Resource Management System** | Cloud consumer's administrator accesses usage/admin portal externally to administer leased IT resources. Cloud provider's administrator uses native UI provided by VIM to perform internal resource management tasks |
| 3 | **SLA Management System** | SLA monitor polls the cloud service by sending polling request messages. Records "up" time and "down" time in log database. Tracks service availability against SLA commitments |
| 4 | **Billing Management System** | Pay-per-use monitor tracks usage and collects data relevant to billing. Forwarded to billing repository. System periodically calculates consolidated usage fees and generates invoice for cloud consumer |

### Cloud Security Mechanisms — 6 Types

| Mechanism | Description |
|-----------|-------------|
| **Encryption** | Protects data confidentiality — at rest and in transit |
| **Hashing** | Ensures data integrity — detects tampering |
| **Digital Signatures** | Verifies authenticity and non-repudiation |
| **Public Key Infrastructure (PKI)** | Manages digital certificates and public/private key pairs |
| **Identity and Access Management (IAM)** | Controls who can access what resources |
| **Single Sign-On (SSO)** | One authentication grants access to multiple systems |
| **Cloud-Based Security Groups** | Firewall rules at the cloud level — control traffic to/from cloud resources |
| **Hardened Virtual Server Images** | Pre-configured VM images with security best practices applied |

### Fundamental Cloud Architectures — 4 Types

**1. Workload Distribution Architecture:**
A redundant copy of Cloud Service A is implemented on Virtual Server B. The load balancer intercepts cloud service consumer requests and directs them to both Virtual Servers A and B to ensure even workload distribution.

**2. Resource Pooling Architecture:**
Multiple cloud service consumers share a pooled set of IT resources. Resources are allocated from the pool on demand. Improves utilisation and reduces cost.

**3. Dynamic Scalability Architecture:**
The process of dynamic horizontal scaling. System automatically adds or removes resources based on demand. (Diagram shows: a) initial state, b) demand increases triggers scale-out, c) scaled state)

**4. Service Load Balancing Architecture:**
The load balancer intercepts messages sent by cloud service consumers and forwards them to virtual servers so workload processing is horizontally scaled. The cloud service implementation includes built-in load balancing logic capable of distributing requests to neighbouring implementations on other virtual servers.

### Hosts, Clusters, and Resource Pools

- **Host:** A single physical server running a hypervisor with VMs
- **Cluster:** Multiple hosts grouped together — provides resource pooling, high availability, load balancing across hosts
- **Resource Pool:** Abstracted pool of CPU, memory, storage, network resources drawn from the cluster — VMs draw from pools rather than specific physical hardware

### vCenter Management Server Architecture

Components of vCenter Server:
- **User Access Control:** Manages who can access what
- **Core Services:** Fundamental vCenter functionality
- **Distributed Services:** Services that span multiple vCenter instances
- **Plug-ins:** Extend vCenter functionality
- **Interfaces:** How users and systems interact with vCenter (client, API, web interface)

### VMotion (Live Migration)

Process of moving a running VM from one physical server to another without downtime:

1. A virtual server capable of auto-scaling experiences increased workload
2. The VIM decides the virtual server cannot scale up because its underlying physical server host is being used by other VMs
3. The VIM commands the hypervisor on the busy physical server to **suspend execution** of the VM
4. The VIM then commands the instantiation of the VM on the **idle physical server**
5. State information (dirty memory pages, processor registers) is **synchronised**
6. The VIM commands the hypervisor at the new physical server to **resume** the VM processing

**Key point:** VMotion enables workload mobility, load balancing, and maintenance without downtime. State synchronisation is the technical enabler.

## Exam-Ready Summary — Weeks 1-3

### Definitions to Memorise

- **Cloud computing (NIST):** On-demand, ubiquitous network access to shared pool of configurable resources, rapidly provisioned and released with minimal management effort
- **Virtualisation:** Abstraction of computer resources to maximise utilisation and reduce cost
- **Hypervisor (VMM):** Software that manages guest OSs and their use of system resources; supports isolation of multiple VMs
- **Type 1 Hypervisor:** Bare-metal, runs directly on hardware (ESXi, Hyper-V)
- **Type 2 Hypervisor:** Hosted, runs on top of host OS (VirtualBox, VMware Workstation)
- **IaaS:** Consumer manages OS+; provider manages hardware+hypervisor
- **PaaS:** Consumer manages apps+data; provider manages OS+middleware+runtime
- **SaaS:** Consumer manages nothing; provider manages everything
- **VMotion:** Live migration of a running VM between physical hosts without downtime

### Cloud Mechanisms to Know

- **6 Infrastructure mechanisms:** Logical Network Perimeter, Virtual Server, Cloud Storage Device, Cloud Usage Monitor, Resource Replication, Ready-made Environment
- **4 Management mechanisms:** Remote Administration System, Resource Management System, SLA Management System, Billing Management System
- **6+ Security mechanisms:** Encryption, Hashing, Digital Signatures, PKI, IAM, SSO, Security Groups, Hardened VM Images

### 4 Fundamental Architectures

1. Workload Distribution (redundancy + load balancing)
2. Resource Pooling (shared resources, multi-tenant)
3. Dynamic Scalability (auto scale out/in)
4. Service Load Balancing (built-in LB in the service)
