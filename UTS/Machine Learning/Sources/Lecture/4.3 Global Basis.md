In the previous section, we established that designing a hypothesis space \(\mathcal{H}\) is fundamentally about choosing a set of basis functions. A basis function is a fixed pattern through which the output varies with respect to the input. Depending on how these patterns are designed, we can roughly categorise them into two types: (i) **local bases**, which adopt a divide-and-conquer strategy—the governing intuition being that “nearby inputs should have similar outputs”; and (ii) **global bases**, which define patterns that span the entire input domain, encoding structure through their functional form rather than through spatial proximity.

In this section, we turn our attention to the global basis design. We begin with the most elementary starting point: using the raw input coordinates \((x_1, \ldots, x_n)\) as the basis. Although this choice is so basic that it is counterintuitive to even call coordinates as “functions” at all, simply combining the input variables (coordinates, \(X_1, \ldots, X_n\)) is a valid and extremely common way to start building a learning system. We will briefly discuss this hypothesis space design, and by examining its limitations, we will motivate the richer families of global basis functions that follow.

## The Linear Model: Using Coordinates as the Basis

The most natural—and historically the first—choice of global basis is simply the input coordinates themselves. The corresponding hypothesis space is the functions of the form:

\[ h(\mathbf{x}) = \phi(s), \qquad s = \sum_{j=1}^{n} w_j \, x_j + b \]

where \(w_j\) is the \(j\)-th weight, \(x_j\) is the \(j\)-th basis function (coordinate), and the constant \(b\) can be thought of as a special weight for the “dummy” basis function that is always equal to 1. The coordinates are taken as functions in the sense that given a data point, \(x_j\) returns a real value that represents a piece of information about the data point. We introduce a transformation \(\phi\) to accommodate a subsequent step following the linear combination of the basis (coordinates). This is often called the *non-linear activation function*, following the mechanism of a biological neuron, which receives incoming signals from synaptic connections, and when the aggregated signal exceeds a certain threshold, the neuron fires and produces an output signal.

A necessary remark is that in the context of a single unit \(h\), the non-linear transformation \(\phi\) will **not** enable the model to capture relationships that need non-linear coupling between the input coordinates.

An intuitive way to understand this characteristic is to investigate the “decision boundary” of the model. In the figure below, we show the coordinates as functions over the unit disc, in the same style as we visualised the basis functions in the previous section. The “decision boundary” is the set of points in the input domain where the function takes a specific value (e.g., 0). The figure also shows a few random combinations of the coordinate basis functions and their decision boundaries. In several examples, the linear score \(s\) is transformed by a non-linear activation \(\phi(s) := \tanh(\gamma s)\), where \(\gamma\) is a positive constant that controls the non-linearity strength. In all examples, the decision boundary is a straight line, which illustrates the fundamental nature (and limitation) of the coordinate basis.

Top: The two coordinate basis functions \(x_1\) and \(x_2\) on the unit disc. Bottom: Four random linear combinations of the coordinates, optionally passed through \(\phi(s) = \tanh(\gamma s)\). In every case the decision boundary is a straight line, illustrating the fundamental limitation of the coordinate basis.

Despite its simplicity, this model is extraordinarily useful in practice. Geometrically, when working with high-dimensional data, the decision boundary (the set of inputs \(\mathbf{x}\) for which \(h(\mathbf{x}) = 0\)) is a hyperplane in \(\mathbb{R}^n\). Whenever the underlying relationship between input and output is approximately linear, this flat hypothesis space is usually sufficient.

Fundamental limitation. However, the linear model has unavoidable structural constraints. A famous example is that it cannot represent the XOR function: where the output is \(+1\) if the two input coordinates have opposite signs and \(-1\) otherwise. The decision boundary of the XOR function is a non-linear curve. This example was historically important, as it disenchanted the early AI researchers who believed that a single-layer perceptron could learn any function, and it motivated the development of feature engineering and, more broadly, neural networks, which we turn to below.

## Extension of Features

The limitation we just identified is fundamentally geometric: the decision boundary in the *original* data space is forced to be a hyperplane. But what if, before applying a linear model, we first re-embed the data into a different space?

Consider a concrete example. Suppose the data lie in the plane \(\mathbb{R}^2\), and the positive class consists of points *inside* a circle centred at the origin. In the original coordinates \((x_1, x_2)\), no straight line separates the two classes. However, introduce a new coordinate \(\psi(\mathbf{x}) = x_1^2 + x_2^2\)—the squared distance from the origin—and lift each point from \(\mathbb{R}^2\) into \(\mathbb{R}^3\) via the map \((x_1, x_2) \mapsto (x_1, x_2, \psi)\). In this lifted space, the circle becomes a *horizontal plane cut*: all interior points satisfy \(\psi r^2\). A single hyperplane \(\psi = r^2\) now separates them perfectly.

The key observation is this: a hyperplane in the *new* space corresponds to a *curved* boundary when projected back to the original space. At the top level, the decision based on the linear combination of variables remains unchanged—we have changed the space in which it operates by changing the variables. This is the geometric essence of feature extension: **re-embedding the data into a richer space so that complex structure in the original domain becomes linearly separable**.

The remaining question is then designing the global basis: which new coordinates \(\{\psi_k(\mathbf{x})\}\) should we choose? This is more famously known as the **feature engineering** or **representation learning** problem.

## Classic Mathematical Foundations

Using generic-purpose functions as the basis to construct other functions is a vital mathematical technique that has been around for centuries and is fundamental to many scientific disciplines. Two of the most famous examples are:

- **Taylor Series** by polynomial basis: Any smooth function \(f(x)\) can be approximated by a polynomial \(f(x) \approx \sum_{n=0}^N a_n x^n\). The basis functions are \(\{1, x, x^2, x^3, \ldots\}\).
- **Fourier Series** by harmonic basis: Any periodic function can be decomposed into a sum of sines and cosines: \(f(x) \approx \sum_k c_k e^{2\pi ikx}\). The basis functions are the harmonic functions \(\{e^{2\pi ikx}\}\).

In both cases, the *family* of basis functions is fixed in advance. The approximation process simply consists of finding the optimal coefficients \(c_k\) to match the target function.

Left: The original data in the plane \(\mathbb{R}^2\) with a circular decision boundary. Middle: The XOR pattern, which is not linearly separable in the original coordinates. Right: A more complex pattern made separable by applying hand-crafted polynomial and harmonic basis functions.

Hand-crafting features requires deep domain expertise. More importantly, it scales poorly. In high-dimensional spaces (like images with millions of pixels), manually designing the right polynomial or Fourier combinations is practically impossible.

## Neural Networks: Automating Basis Construction

A key idea that enables automating the design of basis functions is to use the output of an activated linear unit:

\[ h_k(\mathbf{x}) \leftarrow \phi\!\left(\sum_{j=1}^n w_{kj} x_j + b_k\right) \]

The interpretation is that although the activation transform in every individual \(h_k\) does not change the shape of its individual decision boundary, it has non-linearly wrapped the input space in a respective direction. If one uses the outputs of these activated units as new coordinates and applies a linear model on top of them, the decision boundary of the final model can be a non-linear curve in the original space.

Left and middle: Two random examples of activated linear units—non-linear transformations of the original coordinates. Right: The final decision boundary obtained by combining them in a single-layer network, which is now a non-linear curve in the original space.

It is impressive that the idea of using the output of a primitive unit to form more complicated functions is *recursive* in nature. One need not stop at a single layer of activated linear units. By stacking multiple layers, a neural network can compose basis functions out of other basis functions, and this hierarchical composition allows it to express highly complex functions—which is the key to its success in practice. In practice this scheme is often called a **deep** neural network, and the depth (number of layers) is a crucial factor in determining the expressivity of the model.

Please check out the accompanying notebook demo4_3c_nn.ipynb for a more detailed demonstration of how a neural network composes global basis functions to create complex decision boundaries.

The Necessity of Non-Linearity (\(\phi\)). Notice the activation function \(\phi\). If \(\phi\) were simply the identity function \(f(x) = x\), then \(g_i(\mathbf{x})\) would just be a linear combination of the original inputs. Consequently, the final prediction would just be a linear combination of linear combinations—which mathematically collapses back into a single, flat linear model. *The non-linear activation function is the sole source of the network’s ability to generate genuinely new, non-trivial basis functions.*

Depth vs. Width. Why do we build *deep* networks instead of just very *wide* single-layer networks? By stacking layers, a neural network composes basis functions out of other basis functions. As we will see in the theoretical analysis section, this hierarchical composition allows deep networks to express highly complex functions using exponentially fewer neurons than a shallow network would require.

Code Example. To see this composition in action, consider this Python snippet (similar to the accompanying notebook):

unit_A = lambda x: perceptron_unit(x, randn(2), randn(), act=tanh)
unit_B = lambda x: perceptron_unit(x, randn(2), randn(), act=tanh)

# A neural network is just a perceptron unit stacked on top of other units
unit_nn = lambda x: perceptron_unit(
 np.stack([unit_A(x), unit_B(x)], axis=-1),
 randn(2), randn(), act=tanh
)
The implementation neatly captures the essence of a neural network design: a neural network automatically constructs its own basis (unit_A, unit_B) and then learns how to combine them.

## More on Basis Composition: Gradient Boosting

The linear-combination framework \(F = \sum_m \alpha_m h_m\) is not exclusive to neural networks. Boosting—the technique underlying the popular tools XGBoost and LightGBM—is another concrete and practically important instance of the same idea, but with a different choice of basis family and construction strategy.

The additive model. A boosted model has the form:

\[ F_M(\mathbf{x}) = \sum_{m=1}^{M} \alpha_m h_m(\mathbf{x}) \]

In the context of boosting, the basis \(h_m\) is often called a *weak learner*, typically a *decision stump*—a simple, one-level decision tree that splits the input space based on a single coordinate threshold:

\[ h_m(\mathbf{x}) = \mathbf{1}[x_j > t] - \mathbf{1}[x_j \leq t], \quad j \in \{1,\ldots,n\},\ t \in \mathbb{R}. \]

As in the case of activated linear units, a stump is a global basis: it assigns a value \(+1\) or \(-1\) to *every* point in \(\mathbb{R}^n\) based on one coordinate threshold. The essential difference is that stumps are axis-aligned (depending on only one coordinate).

Sequential, greedy construction. Another key difference lies in how neural networks and boosting models are learned from data. Unlike neural networks, which usually optimise all basis-function parameters jointly, boosting constructs the hypothesis space *one basis at a time*. At each round \(m\), the algorithm selects the stump \(h_m\)—choosing the coordinate \(j\) and threshold \(t\)—that best reduces the *residual error* left by the current ensemble \(F_{m-1}\), then sets the step size \(\alpha_m\) accordingly. The hypothesis space therefore grows incrementally, and the number of basis functions is controlled by early stopping.

Interaction between bases. In boosting, each \(h_m\) is fitted independently to the current residual; the bases do not influence each other’s parameters once placed. In a neural network the basis functions are entangled: changing one weight affects all units in downstream layers.
