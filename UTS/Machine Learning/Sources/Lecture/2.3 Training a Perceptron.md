Some basic aspects to consider in designing a training algorithm 

- 
When: Often in practice, we consider the equivalent question of "when not", a.k.a. the stop condition. The ultimate goal of a training algorithm is to find the optimal member in a model (hypothesis) family. But in practice, it is generally difficult to even tell whether a given one is optimal or close to the optimal. So some condition needs to be derived from the loss criterion. For a binary classifier, a perceptron, in particular, when all training samples are correctly classified is a straightforward condition to test. But it will have issues when it is impossible to achieve 0 training-error, i.e. to have the prediction agree with the target value at every training sample.

There is no straightforward analytical solution to this problem given the data, which is also the case for most other practically useful data models such as the neural networks, support vector machines (SVM) etc. A feasible approach is to adopt the divide-and-conquer strategy: starting from an arbitrary, often randomly initialised set of parameters, we break up the route to the solution (ideally, the optimal parameters set) into many tiny steps. Thus in each of the steps, we improve the parameters in our hands a little bit towards the optimal solution. This is an iterative training process. *What* are the stage-wise goals in the individual steps need to be carefully planned so that the iterative training process could and would lead to the desired solution.
