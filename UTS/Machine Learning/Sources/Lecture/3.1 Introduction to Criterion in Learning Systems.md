# Criterion: Definition and Its Core Role

In the framework of machine learning, our core task is to select a model from the hypothesis space \(\mathcal{H}\) to perform future tasks. This selection process requires a clear criterion to evaluate the model's performance. To serve this purpose, the "criterion" itself must satisfy several fundamental requirements.

This (big) module discusses the "Criterion" — the properties we expect it to possess in machine learning, the mathematical objects and concepts associated with these properties, their counterparts in the actual machine learning process, and the design choices that enable the "Criterion" in our machine learning system to effectively guide the learning of the model.

A core concept is that the criterion is applied to functions, namely elements within the space \(\mathcal{H}\). Therefore, its operational mode must involve evaluating and summarizing the target function across all possible input values of interest. This essentially breaks down into two distinct questions: how to evaluate the function's performance on an *individual* instance, and *over which* individuals these evaluations should be aggregated into an overall evaluation metric.

This module is divided into two parts. The first part introduces how to evaluate the performance on a "single" individual instance, and the second part covers the overall evaluation.

## Loss Function (Instance Loss)

In the mathematical framework of machine learning, a loss function is defined as a measure of the discrepancy between the model's output at a given point and the desired output at that point (if known). Below, we consider some fundamental requirements and considerations for loss functions.

### Computable

Instance loss must be a explicitly defined computable function on the output space of the model:

\[ L: \mathcal{Y} \times \mathcal{Y} \to \mathbb{R}_{\ge 0} \]

Computability, while it may sound trivial, this requirement explicitly governs how real-world information flows into the model. More specifically, it requires us to define a precise space of output variables for the model.

Once the output format is determined, we must use these output variables as primitives to construct a mathematical representation of the ideal state that matches the target value. We then use a loss function to rigorously quantify the discrepancy between the model's output and this ideal state. It is often that the task description itself or the experience data have dictated the form of the output variables, e.g. when you are tasked to predict the price of an asset, there is not much ambiguity about what the format of the model's output should be (a single real number).

However, in some cases, the task description itself does not naturally indicate how to define formal, precise output variables. For example, when training a puppy to sit, the description that the animal has "sat down" is inherently ambiguous. You need to define: i) output variables, such as the angle and angular velocity of each joint; ii) the ideal state, using these output variables as descriptive primitives; and iii) a loss function to measure the discrepancy between the output variables and the ideal state.

As another example, consider object detection in an image. The target in the task-related empirical data is a bounding box and a class label within the image. A rectangle can naturally be described by four numerical values (e.g., the coordinates of the top-left and bottom-right corners), and a category can be described by an integer. However, if we naively define the model's output as just four numbers and a class label, evaluating the discrepancy between the model's output and the target becomes extremely non-trivial (Try it yourself).

### Pseudo-semi-distance

The loss function can be viewed, more or less, as a distance metric. This natural intuition implies that the loss function should have a lower bound, which is reached when the model's output perfectly matches the ideal state. For instance, when a sample is classified into the correct category with 100% confidence, or when the output numerical value exactly meets expectations, the loss function should evaluate to 0.

In practice, a more meaningful articulation of this requirement might be its converse: when the model performs sufficiently well, the learning system should simply apply prudency -- just to avoid penalizing it and stop trying to improve anymore -- rather than limitlessly "rewarding" the model for microscopic improvements toward a "perfect" state. This is of great significance during the optimization process, as it prevents the model from overfitting to specific training samples. In other words, the learning system provides a "bounded happiness," disallowing the model from obsessing over a particular behavior. Sometimes, this cannot be achieved solely through the definition of the distance function and requires the introduction of additional mechanisms within the optimization algorithm.

Additionally, it is worth noting that a loss function often does not need to be a true mathematical distance metric; for example, it may not satisfy symmetry.

\[ L(y, \hat{y}) \neq L(\hat{y}, y) \]

We will see later that the famous cross-entropy loss is an example of such a loss function that does not satisfy symmetry.

### Multiple Modalities

In real-world problems, the ideal state is often not unique. For example, different medical experts might provide different diagnoses for the same case, yet all could be considered reasonable educated guesses. When the training data contains such contradictory labels, the loss function needs to be able to handle this diversity.

A more common scenario is that the nature of the task itself dictates the absence of a unique ideal state. For instance, in unsupervised learning tasks, the goal is to learn a latent structure or representation from the data. Due to the inherent diversity and complexity of the data, there might exist multiple different latent structures or representations that can reasonably explain it. For example, in an image generation task, given a text description, there could be multiple distinct images that all satisfy the description.

### Other Considerations

In addition to the fundamental requirements mentioned above, several other considerations are also important. For example, the computational efficiency of the loss function is a crucial factor. In the context of large-scale datasets and complex models, computing the loss function can become a bottleneck.

Furthermore, optimization stability is another vital consideration. First, we prefer the function to be smooth to facilitate the design of effective optimization algorithms, allowing for continuous search within the model space. Second, we hope the landscape of this function is not overly complex, so that the optimization algorithm does not easily get stuck in suboptimal positions.
