## Defining Candidates

The second component is the **Hypothesis Space**, denoted as \(\mathcal{H}\). A "hypothesis" \(h\) is simply a function that maps inputs to outputs: \(h: \mathcal{X} \to \mathcal{Y}\). The Hypothesis Space \(\mathcal{H}\) is the **set of all candidate functions** we are considering.

When we design a learning system, we must choose this set beforehand. For example, if we are doing linear regression, \(\mathcal{H}\) is the set of all linear functions:

\[ \mathcal{H} = \{ h(x) = w \cdot x + b \mid w \in \mathbb{R}^d, b \in \mathbb{R} \} \]

## The Necessity of Constraints

Why do we need to restrict ourselves to a specific set \(\mathcal{H}\)? Why not search *all possible functions*?

### 1. Finite Memory requires Finite Description

A mathematical function can be an infinitely complex object. To assume an arbitrary mapping \(f: \mathbb{R} \to \mathbb{R}\) requires infinite degrees of freedom. However, a computer has finite memory. Any function we "learn" must be representable by a finite set of bits (e.g., program code or a set of floating-point weights).

Therefore, we can only ever learn functions that have a finite representation. We model this by using a "Function Template" (like a neural network architecture or a linear equation) parameterized by a finite vector of numbers (weights). The set of all functions generatable by this template is our \(\mathcal{H}\).

### 2. Inductive Bias: Less is More

There is a deeper, theoretical reason to restrict \(\mathcal{H}\). If \(\mathcal{H}\) is too large (e.g., "all possible python programs"), we might find a function that perfectly memorizes the training data but fails completely on new data.

By restricting \(\mathcal{H}\) (e.g., to only linear functions, or only smooth functions), the members of \(\mathcal{H}\) are of certain "simplicity" or "structure". This is can be intuitively thought of as being "stiff", so that it can "take shape" be being pinned down using a small number of examples. This is the essence of **Inductive Bias**: the assumptions we make about the form/structure/regularity of the target function make them carry certain "tendencies" to generalize beyond the limited observations.

Of course, as the name has suggested, this is a "bias". It mostly from one's prior knowledge, understanding of the problem and derivation from first principles. It is not from empirical data. By excluding all possibilities that do not fit the bias, we are effectively saying "I believe the true function is one of these". This is a strong assumption. It is very likely that one has pured the baby out with the bathwater, i.e., the true function is not in \(\mathcal{H}\) at all!

However, practice has shown that a well-chosen inductive bias is often a worthwhile bet. The potential of generalization often overweighs the risk of making errors to fit the data. This is a fundamental tension in machine learning: the trade-off between bias and variance, or underfitting and overfitting. We will encounter this issue repeatedly throughout the course.

## Various Types of Hypothesis Spaces

The choice of \(\mathcal{H}\) is a critical design decision. Some common examples include:

- **Linear Models:** \(\mathcal{H}\) consists of all linear functions. This is simple and interpretable but may not capture complex relationships.
- **Neural Networks:** \(\mathcal{H}\) consists of all functions representable by a given neural network architecture. This can capture highly complex patterns but can be harder to interpret and optimize.
- **Decision Trees:** \(\mathcal{H}\) consists of all functions representable by decision trees of a certain depth. This can capture non-linear relationships and interactions between features but may require careful tuning to avoid overfitting.

There are less explicitly defined hypothesis spaces as well, such as kernel methods, k-nearest neighbors, and ensemble methods. We will discuss these in later modules. For now, the focus is on understanding the concept of a hypothesis space and its role in machine learning.
