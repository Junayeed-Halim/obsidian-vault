## From Intuition to Mathematics

In the previous module, we established *what* Machine Learning is: a paradigm shift from defining rules to learning them from data. Now, we must articulate *how* this is achieved mathematically.

To implement the somehow mysterious "probably approximately correctly learning from data" process; it is necessary to frame it into a well-defined mathematical problem. One of the most influential frameworks is the **Statistical Learning Framework**, which considers learning as an optimisation within an abstract space -- the **function space**. This framework provides a rigorous way to understand, define and implement the components of learning and how they interact.

Rigourously, a statistical learning system is defined via four components:

- **The Data Distribution \(P_D\) and \(\mathcal{D}\):** The source of information.
- **The Hypothesis Space \(\mathcal{H}\):** The set of all possible models we are willing to consider.
- **The Criterion (Loss Function) \(L\):** How we measure success.
- **The Algorithm \(\mathcal{A}\):** The computational procedure to find the best model.

Note that, we have **no control over the data distribution \(P_D\)**. We can only observe samples from \(P_D\) (the training set), but we cannot change the underlying distribution itself. The \(P_D\) enters our framework with a role in analytics and design of algorithms, but it is not something we can manipulate directly.

### Interaction of Components and Core Challenges

The components in a learning system works together to perform the core task of extracting patterns from data and making predictions. This is a generic description, and in practice, even a relatively straightforward learning problem can involve numerous design choices and trade-offs, which are related to and influenced by numerous factors and challenges.

As an introduction, there are mainly 3 overarching challenges that we will encounter in the design of learning algorithms:

- **Expressivity:** Is our hypothesis space rich enough to capture the true underlying relationship in the data?
- **Generalization:** How do we ensure that our model performs well on unseen data, not just the training set?
- **Optimization:** Can we efficiently find the best model within our hypothesis space according to our loss function?

The design choices and the challenges are intertwined in complex ways. For example, increasing the expressivity of our hypothesis space (e.g., using a deep neural network) can help capture complex patterns in the data, but it can also lead to overfitting, which hurts generalization. Similarly, choosing a more complex loss function might better capture the nuances of the problem but could make optimization more difficult. We will encounter these issues and engage with them throughout the course. ## Component 1: The Data

Everything starts with data. But "data" is a vague term. In our framework, we formalize it with specific sets and distributions.

### The Spaces

- **The Input Space \(\mathcal{X}\):** This is the set of all possible inputs. If we are analyzing standard images, \(\mathcal{X}\) might be \(\mathbb{R}^{256 \times 256 \times 3}\). If we are predicting house prices based on 10 features, \(\mathcal{X} = \mathbb{R}^{10}\). From the viewpoint of a digital computer, to fix the input space is to fix a certain size of buffer of bits that can encode one input sample. E.g. for an image mentioned above, we can encode it with a buffer of \(256*256*3*8\) bits (assuming 8 bits per pixel per channel).
- **The Output Space \(\mathcal{Y}\):** This is the set of possible answers. In binary classification (e.g., spam vs. not spam), \(\mathcal{Y} = \{0, 1\}\). In regression (e.g., temperature prediction), \(\mathcal{Y} = \mathbb{R}\).

#### Beyond Simple Scalars and Bits:

While introductory courses often focus on binary classification (\(\mathcal{Y} = \{0, 1\}\)) or scalar regression (\(\mathcal{Y} = \mathbb{R}\)), real-world applications frequently demand more sophisticated output structures.

- **Multi-class Classification:** Predicting one of \(K\) mutually exclusive categories (e.g., handwritten digit recognition), where \(\mathcal{Y} = \{1, 2, \dots, K\}\).
- **Structured Prediction:** Problems where the output is a complex object with internal dependencies, such as a sentence in natural language translation (\(\mathcal{Y}\) is the set of all possible sequences of words), a parse tree in syntax analysis, or even another image in image-to-image translation tasks. In these cases, \(\mathcal{Y}\) can be extremely high-dimensional and constrained by grammatical or physical rules.

#### The Central Point:

Defining the learning problem begins with rigorously specifying the **domain** (\(\mathcal{X}\)) and the **codomain** (\(\mathcal{Y}\)). This is not merely a technicality; it constitutes the fundamental *modelling choice* of the machine learning engineer. By fixing these spaces, we obtain a mathematical container that delimits what our function \(f: \mathcal{X} \rightarrow \mathcal{Y}\) can accept and what it can produce.

From a computer science perspective, this is equivalent to defining the **data types** or **formats**. Whether the input is a 16-bit integer or a 4K video stream, and whether the output is a single boolean flag or a generated caption, the learning framework treats them abstractly as elements within defined vector spaces or sets. The learning algorithm's job is to navigate the map between them, regardless of their complexity.

### The Distribution (Advanced but Fundamental)

Crucially, we assume there exists an unknown **Data Distribution** \(P\) over \(\mathcal{X} \times \mathcal{Y}\). While the concept of a joint probability distribution might seem abstract (and effectively is an advanced topic in statistical learning theory), it is the mathematical bedrock that justifies why machine learning works at all.

The world is not random chaos; there is a structure. This distribution \(P(x, y)\) encapsulates the "ground truth" of this structure:

- **Marginal Probability \(P(x)\):** Tells us which inputs are likely to naturally occur. For example, in the space of all possible pixel combinations, natural images (faces, landscapes) occupy a tiny, high-probability manifold, whereas random static noise is extremely unlikely.
- **Conditional Probability \(P(y|x)\):** Tells us the underlying relationship between input and output. If \(x\) is an image of a cat, \(P(y=\text{"cat"}|x)\) should be high. This term also captures intrinsic **noise** or ambiguity (e.g., if an image is blurry, the distribution might assign valid probabilities to both "cat" and "dog").

### The Training Set vs. The "Real World"

In practice, we never see the full distribution \(P\). It is an infinite or astronomically large ocean of possibilities. Instead, we work with a finite **Training Set** \(S\), which serves as our limited window into reality:

\[ S = \{(x_1, y_1), (x_2, y_2), \dots, (x_m, y_m)\} \]

We typically assume these examples are drawn **independently and identically distributed (i.i.d.)** from \(P\). This assumption is critical: it implies that our training set \(S\) is a representative "glimpse" of the broader distribution \(P\).

**The Goal: Generalization**

This distinction between the *sample* (\(S\)) and the *population* (\(P\)) leads to the most important definition in machine learning logic:

- We use the **Training Set** to build our model.
- But we care about the model's performance on the **Distribution \(P\)**.

This is why we evaluate models on a **Test Set**—a collection of examples effectively drawn from \(P\) but **unseen** during training. If a student memorizes the practice exam (overfitting to \(S\)) but fails the final exam (performance on \(P\)), they have not truly learned. Our goal is **Generalization**: performing well on the distribution "out there," not just on the data we have in hand.
