# The Statistical Nature of Learning

It is natural to have remaining doubts about the entire Machine Learning approach. After all, we are not deriving functions from first principles; we are guessing them based on finite data. However, from the information theoretic perspective, this approach is not less rigorous than traditional engineering.

After all, an "arbitrary" function is an object with infinite degrees of freedom. Consider to assign a value \(y\) to each input \(x\) in a continuous domain \(\{0, 0.1, 0.2, \dots, 1\}\), each assignment is essentially a \(11\)-D vector, and there are 11 degrees of freedom for mappings on this discrete domain. If we allow the input values to be chosen from \(\{0, 0.01, 0.02, \dots, 1\}\), then we have a \(101\)-D vector and thus \(101\) degrees of freedom. Pushing the input resolution to be infinitely fine, it is easy to see that the number of degrees of freedom for functions \([0,1] \mapsto \mathbb{R}\) is infinite.

In practice, the description of a mathematical definition or a computational procedure of a function has to be of a finite length. This consists of a fundamental constraint on the possibilities of all functions that can be explored in any task.

Different methods consider varying subsets of the function space (of infinite degrees of freedom). Naturally, people often choose to use simpler subsets of functions, which are considered to be more "regular" and exhibit more "nice structures". The structures are often connected to common properties of the physical world, such as smoothness or mean-value properties.

From this perspective, the data-driven approach is to specify a function by explicitly describing its results on a finite set of inputs (the training data), and then to extrapolate to the rest of the input space using assumptions about the function's regularity. This is a different but valid way of defining a function compared to writing down an explicit formula or algorithm, where the formula/computational algorithm can be thought of as a "compressed" representation of the function that implicitly encodes its behavior across the entire input space, i.e. a "nice structure".

## It Works: PAC Learning

Now we see that the general idea is to specify a function as:

At \(x^{(1)}\), the value should be \(y^{(1)}\);
At \(x^{(2)}\), the value should be \(y^{(2)}\);
...
At \(x^{(N)}\), the value should be \(y^{(N)}\);
**Plus** that the function should be "nice", not varying wildly, e.g. outputting similar values for similar inputs.

The central question is that whether the specification-by-examples can be made "detailed enough" to "pin down" a function? In short, we PROBABLY CAN, if we have a clear definition of "pinning down".

We will study the problem under the framework of **Statistical Learning Theory**, specifically, **PAC Learning** (Probably Approximately Correct), which provides the conditions under which learning is feasible. The key idea is that given enough examples, the *probability* of ending up with a function that differs significantly from the true underlying function (*approximately correct*) is very low.

### Formal Description

The formal description is as follows:

\[ \begin{align} \hat{h} &= \textrm{Minimizer of training error} \\ P(\textrm{error of } \hat{h} > \epsilon) &

where \(\epsilon\) represents the error tolerance (how "approximately correct" we need to be) and \(\delta\) represents the confidence level (how "probable" the guarantee is).

We will study the concepts in this framework in more detail in the following-up modules. For now, the takeaway is that sufficient data can probably lead us to a good enough approximation of the target of interest, even if we do not have a closed-form formula or an explicit algorithm of the target.
