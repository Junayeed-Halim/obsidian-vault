# Model Design III: Motivating Unsupervised Learning

Everything we have done so far has been organised around a fixed asymmetry: there is an input \(\mathbf{x} \in \mathcal{X}\) and an output \(y \in \mathcal{Y}\), and the task is to learn a function \(h : \mathcal{X} \to \mathcal{Y}\) that approximates the unknown relationship between them. Hypothesis design—whether through global basis functions, decision trees, or kernel methods—is the discipline of specifying *which* functions \(h\) are admissible, i.e. of carving out a structured hypothesis space \(\mathcal{H} \subset \{h : \mathcal{X} \to \mathcal{Y}\}\).

This setup is powerful, but it rests on a choice that we have quietly taken for granted: the partition of the observable variables into “inputs” and “outputs”. Two complementary lines of reasoning suggest that this partition is not always natural—or even necessary.

## Perspective 1: Dropping the Input/Output Asymmetry

In the supervised framework, the role labels—“this is \(\mathbf{x}\), that is \(y\)”—are assigned *before* learning begins. They reflect a particular *use case*: the practitioner has decided in advance which quantities will be observed at prediction time and which will be predicted. But this assignment is a modelling choice, not an intrinsic property of the data.

Consider an image. One can ask: given the left half of the image, predict the right half (an in-painting problem). Alternatively, one can ask: given the top half, predict the bottom half. Or: given the colour channels, predict the depth channel. Each question induces a different supervised problem, with a different \(\mathcal{X}\) and a different \(\mathcal{Y}\). Yet all these questions are about the *same* underlying object—the joint distribution over all the pixel values.

This observation suggests a more general programme: rather than committing to one input/output split, describe the *joint* structure of all variables together, and then let the downstream user decide which partition suits their application. More formally, if we collect all observed variables into a single vector \(\mathbf{v} = (\mathbf{x}, y)\), the task becomes characterising the relationship among the components of \(\mathbf{v}\)—without privileging any one component as the “target”.

This is the first motivation for unsupervised learning: it is the programme of describing the structure of a joint variable, rather than a conditional relationship between a pre-ordained input and output. Every supervised problem can then be seen as a special case—a conditional slice through the learned joint structure—while the joint model itself remains agnostic to any particular use.

## Perspective 2: Learning the Kernel from Data

A second, more technical motivation emerges directly from the kernel methods we studied in the previous section.

Recall the central operation of a kernel method: a kernel function \(k(\mathbf{x}, \mathbf{x}')\) measures the similarity between two data points, and this similarity is used to “spread” the influence of each training point \(\mathbf{x}_i\) across the input space. The resulting hypothesis

\[ h(\mathbf{x}) = \sum_{i=1}^{N} \alpha_i\, k(\mathbf{x}_i, \mathbf{x}) \]

propagates the label \(y_i\) (encoded in \(\alpha_i\)) to nearby query points. Crucially, the similarities \(k(\mathbf{x}_i, \mathbf{x})\) depend only on the input points—the labels \(\{y_i\}\) play no role in defining the geometry of the kernel.

The kernel is specified by hand. In everything we have discussed so far, the kernel function \(k\) was chosen *a priori*: we selected the RBF kernel, or the polynomial kernel, or the linear kernel, and fixed its hyperparameters (e.g. the bandwidth \(\sigma\)). The data was then used only to fit the coefficients \(\boldsymbol{\alpha}\). This is a strong modelling assumption: the notion of “similarity” encoded in \(k\) is imposed on the data, not inferred from it.

A natural question arises: *can the data itself tell us what kernel to use?*

A first hint: the Voronoi partition. We have already seen a primitive answer to this question. When we placed basis-function centres at the training points and formed a Voronoi partition, the shape of each cell was not prescribed—it was determined entirely by the configuration of the other training points. In dense regions, the cells were small; in sparse regions, they were large. The geometry of the partition, and hence the notion of “nearness” it encodes, was an emergent property of the data distribution. This is the germ of the idea: use the data to shape the similarity structure.

Kernels through neural network training. A more precise instance of data-driven kernel learning comes from the connection between neural networks and Gaussian Processes established in the previous section. Recall that an infinitely wide single-layer network, at random initialisation, defines a fixed Gaussian Process:

\[ \mathrm{Cov}\!\bigl(f(\mathbf{x}),\, f(\mathbf{x}')\bigr) = k_{\mathrm{NNGP}}(\mathbf{x}, \mathbf{x}'), \]

where the kernel \(k_{\mathrm{NNGP}}\) is determined by the architecture and the weight distribution alone—it does not depend on any training data. At infinite width, the kernel is effectively *fixed* once the architecture is chosen.

For a finite-width network, the situation is richer. As gradient descent adjusts the weights to minimise the supervised loss, the feature map induced by the network—and hence the effective kernel \(k(\mathbf{x}, \mathbf{x}')\) measuring the similarity between two inputs in the learned representation—changes. Training a neural network is therefore, at least in part, an act of *adapting the kernel to the data*: the network learns which pairs of inputs should be considered similar, in the service of predicting \(y\) more accurately. One can think of this as sculpting the “geometric terrain” of \(\mathcal{X}\)—warping the input space so that points with similar labels cluster together and points with dissimilar labels are pushed apart.

From supervised to unsupervised kernel learning. In supervised learning, this terrain is shaped by the label signal \(y\): the kernel is tuned so that the function \(h(\mathbf{x}) = \sum_i \alpha_i k(\mathbf{x}_i, \mathbf{x})\) fits the training pairs \(\{(\mathbf{x}_i, y_i)\}\) well. But there is nothing sacred about \(y\) as the source of supervision. One could equally ask: is there a natural training objective, defined *purely in terms of \(\mathbf{x}\)*, that encourages the kernel to capture the intrinsic structure of the input distribution? If such an objective exists, we can train the kernel—or the neural network that implicitly defines it—without ever observing any labels. This is precisely the domain of unsupervised learning.

The two perspectives compared. The two motivations above approach unsupervised learning from different angles, and it is worth making their difference explicit.

- **Perspective 1 (symmetry of variables)** starts by questioning the input/output asymmetry. The inputs \(\mathbf{x}\) lose their privileged status, and the goal becomes modelling the structure of the full joint variable \(\mathbf{v} = (\mathbf{x}, y)\)—or, equivalently, the entire data cloud, with no variable singled out as the response.
- **Perspective 2 (data-driven kernel)** starts from the kernel \(k(\mathbf{x}, \mathbf{x}')\), which is defined on *pairs* of input points and captures their pairwise similarity. Here the response \(y\) is discarded not because it lacks meaning, but because an alternative objective—one that exploits the geometry of \(\mathcal{X}\) alone—is used to shape the kernel. The output of learning is not a function \(h : \mathcal{X} \to \mathcal{Y}\) but a similarity structure over \(\mathcal{X}\).

Both perspectives converge on the same conclusion: meaningful structure can be extracted from data without a pre-assigned target variable, and the resulting representations can serve as the foundation for a wide range of downstream tasks. We will glance at a few specific techniques that operationalise this idea.

# Extracting Structure from Data: Unsupervised Learning
## Principal Component Analysis (PCA)

A classic method of representing the structure of a data population is Principal Component Analysis (PCA).

The central object is the covariance matrix \(\Sigma\) of the data distribution, whose \((i,j)\) entry records how the \(i\)-th and \(j\)-th variables co-vary:

\[ \Sigma_{i,j} = \mathrm{Cov}(x_i, x_j) = \mathbb{E}\bigl[(x_i - \mu_i)(x_j - \mu_j)\bigr], \]

where \(\mu_i = \mathbb{E}[x_i]\) is the mean of the \(i\)-th variable. A large positive entry \(\Sigma_{i,j}\) indicates that variables \(i\) and \(j\) tend to rise and fall together; a near-zero entry indicates near-independence. The full covariance matrix therefore encodes the entire second-order statistical structure of the data—it is a compact description of the pairwise relationships among all observed variables.

When the number of variables is large—for instance, a \(64\times 64\) greyscale image has \(d = 4{,}096\) pixel variables—the covariance matrix \(\Sigma\) is a \(4{,}096 \times 4{,}096\) object with over sixteen million entries. Storing and interpreting it directly is impractical. The key question is whether a few underlying *directions* can account for most of the variance: if the data cloud, although nominally \(d\)-dimensional, is nearly confined to a low-dimensional subspace, then a small number of basis vectors suffices to describe it.

Mathematically, this is answered by the spectral decomposition of the covariance matrix. Because \(\Sigma\) is symmetric and positive semi-definite, it admits the eigen-decomposition

\[ \Sigma = U \Lambda U^\top = \sum_{k=1}^{d} \lambda_k \mathbf{u}_k \mathbf{u}_k^\top, \]

where \(\mathbf{u}_1, \mathbf{u}_2, \ldots, \mathbf{u}_d\) are the orthonormal eigenvectors of \(\Sigma\), and \(\lambda_1 \geq \lambda_2 \geq \cdots \geq \lambda_d \geq 0\) are the corresponding eigenvalues sorted in decreasing order. Each eigenvalue \(\lambda_k\) equals the variance of the data when projected onto the direction \(\mathbf{u}_k\):

\[ \lambda_k = \mathrm{Var}\!\bigl(\mathbf{u}_k^\top \mathbf{x}\bigr). \]

Hence the eigenvectors with the largest eigenvalues are the directions along which the data varies most—they are the *principal components*. By retaining only the top \(K\) eigenvectors, we obtain the best rank-\(K\) approximation of \(\Sigma\), and correspondingly the best \(K\)-dimensional linear subspace for representing the data.

*Top row*: the first few PCA basis vectors (principal components) of an image dataset, displayed as images. Each basis vector \(\mathbf{u}_k\) is an eigenvector of the sample covariance matrix \(\hat\Sigma\), ordered by decreasing eigenvalue. *Bottom row*: step-by-step reconstruction of a sample image by accumulating principal components one at a time.

Given the top-\(K\) principal components, every data point \(\mathbf{x}\) can be approximated as a linear combination of the basis vectors, centred at the data mean \(\boldsymbol{\mu}\):

\[ \mathbf{x} - \boldsymbol{\mu} \;\approx\; \sum_{k=1}^{K} a_k\, \mathbf{u}_k, \qquad a_k = \mathbf{u}_k^\top(\mathbf{x} - \boldsymbol{\mu}). \]

The coefficient \(a_k\) is simply the projection of the centred data point onto the \(k\)-th principal direction. Each data sample is thus represented not by its \(d\) raw pixel values but by \(K \ll d\) real numbers \(a_1, \ldots, a_K\)—a dramatic compression that is lossless along the directions of greatest variance and discards only the low-variance residual.

In the provided demo notebook, you can verify that retaining the first \(100\) principal components already yields a visually faithful reconstruction of the original \(4{,}096\)-dimensional image—a compression ratio of roughly \(40:1\).

The \(K\) principal components \(\{\mathbf{u}_k\}_{k=1}^K\) form a set of *global, linear basis functions*, and every compressed data point is simply a coordinate vector in the subspace they span. PCA is therefore the canonical instance of unsupervised *linear dimensionality reduction*: it discovers, from data alone and with no label signal, a \(K\)-dimensional linear subspace that captures the dominant structure of the data distribution. The linear correspondence between the raw and the compressed representation naturally limits the capacity of the model to represent points that lie within a linear subspace of the original space.

However, the idea of \(\mathcal{X} \xrightarrow{\text{encode}} \mathcal{Z} \xrightarrow{\text{decode}} \mathcal{X}\) can be generalised to nonlinear transformations, which leads to the powerful family of autoencoders.

# Autoencoders

PCA projects data onto a linear subspace. If the data lies on a curved manifold—a sphere, a spiral, or the set of all natural images—linear hypotheses are insufficient to capture its structure. Alternatively, if one attempts to describe the data using \(k\) modes and insists that data is represented as a linear combination of these modes, then to approximate the data to a certain level of accuracy, the number of modes \(k\) may be excessive, larger than the necessary intrinsic dimensionality. (Imagine the Swiss roll data: the distribution is effectively 1D, but it curves through 2D space.) An autoencoder removes this restriction by replacing the linear projection and reconstruction with two neural networks.

## The Encoder–Decoder Architecture

An autoencoder consists of a pair of functions:

\[ \begin{aligned} f_{\mathrm{enc}} &: \mathcal{X} \to \mathcal{Z}, &\quad \mathbf{z} &= f_{\mathrm{enc}}(\mathbf{x}), \\ f_{\mathrm{dec}} &: \mathcal{Z} \to \mathcal{X}, &\quad \hat{\mathbf{x}} &= f_{\mathrm{dec}}(\mathbf{z}). \end{aligned} \]

The encoder \(f_{\mathrm{enc}}\) maps each input \(\mathbf{x} \in \mathcal{X}\) to a lower-dimensional latent code \(\mathbf{z} \in \mathcal{Z}\), where \(\dim \mathcal{Z} \ll \dim \mathcal{X}\). The decoder \(f_{\mathrm{dec}}\) attempts to invert this map, reconstructing \(\hat{\mathbf{x}}\) from \(\mathbf{z}\) alone. Both functions are typically realised as neural networks.

The two networks are trained jointly to minimise the reconstruction loss

\[ \mathcal{L}(\theta, \phi) = \frac{1}{N} \sum_{i=1}^{N} \bigl\| \mathbf{x}_i - f_{\mathrm{dec}}\!\bigl(f_{\mathrm{enc}}(\mathbf{x}_i)\bigr) \bigr\|^2, \]

where \(\theta\) and \(\phi\) are the parameters of the decoder and encoder respectively. Recall the discussion about the kernel-learning perspective: in the standard supervised setting, the training objective is to make the network’s output \(h(\mathbf{x})\) match the label \(y\). *En route* to producing a good predictor, the network learns task-significant representations of the input. Here the target is removed entirely: the reconstruction objective depends only on \(\mathbf{x}\), with no labels required. The entire pipeline \(f_{\mathrm{dec}} \circ f_{\mathrm{enc}} : \mathcal{X} \to \mathcal{X}\) is trained to approximate the identity function on the training data. This is *self-supervised* learning: the target output is the input \(\mathbf{x}_i\) itself.

## Architectural Inductive Bias

The reconstruction objective alone does not determine what kind of structure the autoencoder will discover. A sufficiently powerful encoder and decoder could, in principle, memorise the training corpus and learn nothing transferable. What steers the model towards meaningful representations is the inductive bias built into the architecture: structural constraints that make certain patterns preferred and easier to emerge during training, forcing the network to discover the regularities that the designer believes are genuinely present in the data. The bottleneck is the most universal such constraint. Different architectural priors are also found important in different practical tasks and data modalities. After introducing the bottleneck in general autoencoders, we briefly glance at two specific examples: convolutional autoencoders for images, and Transformer-based models for language.

### The Bottleneck and What It Forces

The key structural ingredient is the bottleneck: the latent space \(\mathcal{Z}\) has strictly fewer dimensions than \(\mathcal{X}\). Without this constraint, the trivially optimal solution is the identity map—the encoder copies \(\mathbf{x}\) verbatim and the decoder returns it unchanged. The bottleneck makes verbatim copying impossible and forces the encoder to compress: it must discard information that does not help reconstruction, while retaining the structure that does.

What does the encoder retain? Roughly, the directions of greatest variance—the features most consistently present across the data population. In this sense an autoencoder can be seen as a *nonlinear generalisation of PCA*: where PCA is constrained to find a linear subspace, an autoencoder can discover a curved *manifold* of dimension \(\dim \mathcal{Z}\) that approximates the data cloud. The latent code \(\mathbf{z}\) is then the coordinate of each data point on this learned manifold.

### Convolutional Autoencoders: Spatial Locality as Prior

For image data, more effective architectural priors are available. A fully-connected encoder treats every pixel as an independent input; it has no built-in notion that nearby pixels are more likely to be related than distant ones, and it must learn that fact from scratch. A convolutional autoencoder instead instantiates the encoder and decoder as convolutional neural networks, embedding two structural priors that are highly appropriate for spatially organised data:

- **Local connectivity**: each unit in a convolutional layer receives input from a small spatial neighbourhood, reflecting the fact that meaningful image features (edges, textures, object parts) are spatially contiguous.
- **Translation equivariance**: the same filter is applied at every spatial location, encoding the prior that a feature—say, a horizontal edge—is equally meaningful wherever it appears in the image.

The encoder progressively downsamples the spatial dimensions (via strided convolutions or pooling), compressing the image into a compact feature map, while the decoder upsamples back to the original resolution using transposed convolutions. Simply put, the output value at a location \((x,y)\) is computed by a weighted sum of the input values in a corresponding local region \([x \pm \Delta,\, y \pm \Delta]\). This concept will be discussed in more detail in the topic dedicated to neural network models.

A natural extension of this idea is to add skip connections that route feature maps from intermediate encoder layers directly to the corresponding decoder layers, bypassing the bottleneck for fine spatial detail. This is the U-Net architecture, which has become the workhorse of image segmentation, medical imaging, and diffusion-model decoders. Conceptually, the skip connections allow the decoder to recover high-frequency spatial detail—which would otherwise be lost through the bottleneck—while still benefiting from the high-level semantic representation produced by the deep encoder layers. ### Transformer Autoencoders: Global Dependencies as Prior

Natural language presents a different geometry. A sentence is a sequence of discrete tokens (words or sub-word units), and the relationships between tokens are not primarily spatial—the subject of a sentence may be separated from its verb by an arbitrarily long subordinate clause. Convolutional filters, with their fixed local receptive fields, are poorly suited to capture such long-range dependencies.

The self-attention mechanism of the Transformer addresses this directly. In a self-attention layer, each token computes a weighted sum over *all* other tokens in the sequence, with weights determined by the pairwise compatibility of the tokens’ current representations:

\[ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V, \]

where \(Q\), \(K\), \(V\) are the query, key, and value matrices derived from the input, and \(d_k\) is the key dimension. The attention matrix \(\mathrm{softmax}(QK^\top / \sqrt{d_k})\) plays the role of a *data-adaptive kernel*: it measures the similarity between every pair of tokens, and these similarities are used to aggregate information across the sequence. In this sense, a Transformer is another concrete instance of Perspective 2 from our motivation: it learns a data-driven pairwise similarity structure (the attention pattern) from data, without any externally imposed labels.

A Transformer autoencoder applies this architecture to the self-supervised reconstruction task. Each layer’s computation produces a new sequence of token representations. The encoder transforms the input sequence using stacked self-attention layers, followed by a bottleneck that compresses the sequence-level representation, e.g. by averaging the token representations, taking a special token’s representation, or applying a learned projection. The decoder attends over this latent representation to reconstruct the original.

A particularly influential variant is Masked Language Modelling (MLM), exemplified by **BERT** (Devlin et al., 2018): a random subset of input tokens is replaced by a [MASK] placeholder, and the model is trained to predict the original tokens at those positions. This is precisely an autoencoder whose “bottleneck” is informational rather than dimensional: the masking forces the model to infer missing tokens from context, and the attention mechanism provides the means to gather that context from anywhere in the sequence.

#### Autoregressive Models: A Closely Related Variant ★

A further variant changes the masking rule: instead of masking random tokens and reconstructing them in parallel, the model is constrained to predict the *next* token given all preceding ones:

\[ p(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} p(x_t \mid x_1, \ldots, x_{t-1}). \]

The self-supervision signal is derived from the data alone; the “label” at position \(t\) is simply the token that actually appears there. Nevertheless, it inherits the same core philosophy: use the structure of the data itself to define the training signal, and thereby learn rich representations without any externally provided labels. The **GPT** model family (Radford et al., 2018 onwards) is the canonical representative of this paradigm and has proven extraordinarily effective for language modelling and generation.
